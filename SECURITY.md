# Security reporting

## Report privately

Please do not publish suspected vulnerabilities, exploit instructions, credentials, private logs, or customer data in a public issue or pull request.

Use GitHub's **Report a vulnerability** option in this repository's Security tab **if it is enabled**. If that option is unavailable, use an existing private support/contact channel with the repository owner and ask for a secure reporting route before transmitting sensitive details. No unverified security email address is published here.

Do not use ordinary public feature-request forms to submit secrets or vulnerability evidence.

## Useful initial information

Privately provide a concise description, the affected feature or interface, observed impact, the time observed, and a minimal reproduction using an account and environment you are authorized to test. Redact credentials and personal data. State whether the finding is a confirmed observation or a hypothesis.

Do not download unrelated records, access another tenant, disrupt service, perform load testing, bypass payment processing, or continue exploitation merely to prove a concern. Public documentation is not authorization for security testing.

## Response expectations

Reports are reviewed through the maintainer's private process. This file does not establish a response-time SLA, a bug-bounty reward, a testing safe-harbor agreement, or permission to publish a finding. Coordinate disclosure privately.

## Scope

This repository contains public explanations, not the private implementation. A potential issue in the live platform should still be reported privately. An ordinary documentation typo without sensitive implications can be submitted as a public issue or pull request.

See [Security and trust boundaries](docs/04-security-and-trust.md) for the public control summary and its assurance limits.
